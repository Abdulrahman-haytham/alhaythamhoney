# الهيثم — نحل وعسل

Next.js App Router + PostgreSQL/Prisma. واجهة متجر عربية، لوحة إدارة للمنتجات والخلطات والمدونة والتقييمات والاستديو، وإتمام الطلب عبر واتساب فقط. لا دفع إلكتروني؛ تتبّع الكمية اختياري لكل منتج (شارة «بقي X فقط»).

## حسابات الزبائن

الدخول بلا كلمة مرور: بريد → رمز 6 أرقام (10 دقائق، 5 محاولات) → للجديد الاسم والهاتف فقط. البريد للرمز، والهاتف للتوصيل والرسائل الجماعية. اضبط `SMTP_URL` و`MAIL_FROM` في الإنتاج؛ محلياً تُكتب الرموز في `data/outbox.log`.

الحساب لا يغيّر شيئاً من المتجر لغير المسجّلين — يضيف فقط: شارة «حساب موثّق» على التقييمات، كوبونات «للأعضاء» و«مرة لكل حساب»، المشاركة في السحب الأسبوعي برمز المرطبان، نقاط الولاء والإحالة وكوبون الترحيب (إن فعّلها الأدمن)، وتتبّع الطلبات من الحساب.

## ما يتحكم به الأدمن (وميزانيته)

كل ميزة تكلّف مالاً لها مفتاح تشغيل وسقف في `/admin/settings`:

| الميزة              | المفتاح                                   | السقف / الميزانية                                                          |
| ------------------- | ----------------------------------------- | -------------------------------------------------------------------------- |
| خصم الكمية          | `tieredPricingEnabled`                    | الشرائح لكل منتج من محرّره                                                 |
| العروض التلقائية    | `promotionsEnabled` + فعّال/معطّل لكل عرض | ميزانية شهرية لكل عرض بالليرة (0 = بلا سقف)                                |
| الشحن حسب المحافظة  | `shippingZonesEnabled`                    | التكلفة والمدة لكل محافظة من جدول المناطق                                  |
| نقاط الولاء         | `loyaltyEnabled`                          | معدّل الكسب، قيمة النقطة، الحد الأدنى، النسبة القصوى، سقف الاستبدال الشهري |
| ادعُ صديقاً         | `referralEnabled`                         | نسبة الكوبون وسقفه ومدته، وأقصى عدد إحالات في الشهر                        |
| كوبون الترحيب       | `welcomeCouponEnabled`                    | النسبة والسقف والحد الأدنى والمدة وأقصى عدد في الشهر                       |
| «أعلمني عند التوفر» | `stockAlertsEnabled`                      | —                                                                          |
| بريد السلة المتروكة | `abandonedCartEmailEnabled`               | بعد كم ساعة، رسالة واحدة لكل سلة                                           |
| مغذّي المنتجات      | `productFeedEnabled`                      | —                                                                          |
| طلبات الجملة        | `wholesaleEnabled`                        | —                                                                          |

كل تعديل من اللوحة يُسجَّل في `/admin/activity` مع القيم قبل وبعد.

## التشغيل محلياً

المتطلبات: Node.js 22 أو أحدث، PostgreSQL 16.

```bash
cp .env.example .env
# عدّل الاتصال وكلمة مرور الأدمن وسر الجلسة أولاً
npm ci
npm run db:deploy
npm run db:seed
npm run dev
```

الموقع: http://localhost:3005 — الإدارة: /admin/login.

Seed آمن لإعادة التشغيل: لا يعيد تعيين كلمات المرور أو الأسعار أو الصور المعدّلة. المنتجات والخلطات الجديدة تُنشأ **مخفية**، لأن الأسعار والمحتوى الأولي أمثلة تحتاج مراجعة من صاحب المتجر. انشرها من لوحة الإدارة بعد مراجعتها.

## VPS

التعليمات الكاملة: [deploy/VPS.md](deploy/VPS.md).

- Docker Compose: PostgreSQL مستقل، migrations قبل بدء التطبيق، والتطبيق بمستخدم غير root.
- الاستديو في volume دائم، وليس داخل public أو صورة Docker. يظل رابط /uploads/studio/... صالحاً بعد إعادة النشر.
- Nginx على الخادم ينهي HTTPS ويحدّ من حجم الطلبات والمحاولات. منفذ التطبيق مربوط بـ127.0.0.1 فقط.
- واجهات الكتابة تتحقق من Origin، وجلسات الأدمن HttpOnly وموقّعة بسر إلزامي. حدود المحاولات مشتركة في PostgreSQL.
- رفع الملفات يفحص النوع الفعلي والحجم، ويرفض SVG/HTML. تنزيل الفيديو يدعم Range.
- تغيير صورة منتج يتم برفعها من الاستديو ثم نسخ رابطها إلى محرر المنتج؛ لا يمكن حذف صورة مستخدمة في منتج أو خلطة.
- الصفحات المعتمدة على البيانات تُنشأ على الخادم وقت الطلب؛ **البناء لا يحتاج اتصالاً بقاعدة البيانات ولا أسرار الإنتاج**. هذا يختار حداثة الأسعار وسهولة النشر مقابل استعلامات أكثر، وهو مناسب لكتالوج صغير. راقب الحمل قبل إضافة cache.
- ملفات الاستديو ليست جزءاً من Git ولا نسخ التطبيق؛ انسخها احتياطياً مع القاعدة.
- روابط المنتجات الحالية ثابتة لحماية SEO. إخفاء منتج يجعله غير متاح مباشرة ويزيله من Sitemap.

## الاختبارات

```bash
npm run lint
npm run typecheck
npm run test:run
npm run format:check
NEXT_PUBLIC_SITE_URL=https://alhaythamhoney.sy npm run build
npm start
```

الاختبارات الوحدوية تختبر الجلسات والحدود والـAPI وحساب الخلطات والسلة وvCard والملفات. اختبارات SQL تعمل داخل PGlite (PostgreSQL/WASM)، ولا تستبدل اختبار PostgreSQL 16 الفعلي.

CI في .github/workflows/ci.yml يستخدم PostgreSQL 16: يطبق migrations مرتين، يفحص عدم وجود اختلاف بين القاعدة والمخطط، ويبني ثم يجري اختبارات Playwright على الموبايل. لا ينشر الموقع تلقائياً.

Next.js مثبّت على 16.3.5. يوجد override محدد لـdeepmerge-ts 8 داخل أدوات Prisma لمعالجة التنبيه الأمني دون تغيير الإصدار الرئيسي لـPrisma؛ راجعه عند ترقية Prisma. افحص اعتماديات الإنتاج بـ`npm audit --omit=dev` دورياً.

لتشغيل اختبارات المتصفح محلياً، استخدم **قاعدة اختبار فارغة فقط** اسمها ينتهي بـ_test، وNEXT_PUBLIC_SITE_URL=http://127.0.0.1:3005 عند البناء والاختبار معاً:

```bash
npx playwright install chromium
npm run db:deploy
npm run build
npm run test:e2e
```

اختبارات E2E تضيف حساب e2e-admin ومنتج e2e-honey داخل قاعدة الاختبار فقط، وترفض عنوان موقع خارجي. لا تستخدم إعدادات الإنتاج معها.

## قيود يجب مراجعتها قبل الإطلاق

- مراجعة الأسعار والأوزان، أجرة الشحن وحد الشحن المجاني في src/lib/config.ts.
- مراجعة النصوص والادعاءات الصحية، البيانات التجارية والبريد والعنوان وساعات العمل؛ هذه التعديلات البرمجية ليست تدقيقاً طبياً أو قانونياً للمحتوى.
- متابعة موافقة HTTPS وGoogle Search Console، وتجربة QR مطبوع، وطلب واتساب فعلي، ورفع فيديو ثم إعادة النشر والتأكد من بقائه.
- أكواد أحداث التحليلات لا تجمع بيانات ما لم تربط مزوّد التحليلات فعلياً؛ لا توجد لوحة أرباح أو تحويلات مؤكدة.
- PWA تحفظ السلة محلياً وتعرض صفحة اتصال بديلة، ولا تخزّن صفحات الأسعار أو الإدارة دون اتصال.
- تدوير ADMIN_SESSION_SECRET يبطل جميع جلسات الأدمن. Seed لا يغيّر كلمة مرور حساب موجود.

مراجع التنفيذ: [استضافة Next.js ذاتياً](https://nextjs.org/docs/app/guides/self-hosting)، [Web App Manifest](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/manifest).
