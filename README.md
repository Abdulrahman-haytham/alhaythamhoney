# الهيثم — نحل وعسل

Next.js App Router + PostgreSQL/Prisma. واجهة متجر عربية، لوحة إدارة للمنتجات والخلطات والمدونة والتقييمات والاستديو، وإتمام الطلب عبر واتساب فقط. لا دفع إلكتروني ولا إدارة مخزون أو توريد. الأحجام وكميات العميل تصف الطلب فقط.

خطة التطوير وقرارات العمل: [docs/DEVELOPMENT_PLAN.ar.md](docs/DEVELOPMENT_PLAN.ar.md).

## حسابات الزبائن

الدخول بلا كلمة مرور: بريد → رمز 6 أرقام (10 دقائق، 5 محاولات) → للجديد الاسم والهاتف فقط. البريد للرمز، والهاتف للتوصيل والرسائل الجماعية. اضبط `SMTP_URL` و`MAIL_FROM` في الإنتاج؛ محلياً تُكتب الرموز في `data/outbox.log`.

الحساب لا يغيّر شيئاً من المتجر لغير المسجّلين — يضيف فقط: شارة «حساب موثّق» على التقييمات، كوبونات «للأعضاء» و«مرة لكل حساب»، والمشاركة في السحب الأسبوعي برمز المرطبان.

## التشغيل محلياً

المتطلبات: Node.js 22 أو أحدث، PostgreSQL 16.

```bash
cp .env.example .env
# عدّل الاتصال وكلمة مرور الأدمن وسر الجلسة أولاً
npm ci
npm run db:deploy
npm run db:seed
npm run dev
```

الموقع: http://localhost:3005 — الإدارة: /admin/login.

Seed آمن لإعادة التشغيل: لا يعيد تعيين كلمات المرور أو الأسعار أو الصور المعدّلة. المنتجات والخلطات الجديدة تُنشأ **مخفية**، لأن الأسعار والمحتوى الأولي أمثلة تحتاج مراجعة من صاحب المتجر. انشرها من لوحة الإدارة بعد مراجعتها.

## الوظائف

| المسار                | الوظيفة                                                                              |
| --------------------- | ------------------------------------------------------------------------------------ |
| /admin/products       | إضافة وتعديل المنتجات، السعر، الصورة، التفاصيل، التوفر، والنشر                       |
| /admin/mixtures       | أسعار الخلطات وحدود المكونات (مطلقة) وأحجام المرطبان والنشر                          |
| /admin/articles       | كتابة المقالات وتعديلها (Markdown + صور)، مسودّات ونشر مجدول، وربطها بالمنتجات       |
| /admin/coupons        | كوبونات خصم (نسبة/مبلغ، حد أدنى، سقف، تواريخ) تُطبَّق في السلة                       |
| /admin/draws          | السحب الأسبوعي: توليد رموز المرطبانات (CSV للطباعة)، فتح سحب، اختيار الفائز عشوائياً |
| /admin/customers      | حسابات الزبائن وتصدير الأرقام للرسائل الجماعية                                       |
| /account              | حساب الزبون: دخول برمز بريدي بلا كلمة مرور، بياناته، مشاركاته في السحب               |
| /draw                 | صفحة السحب العامة: إدخال رمز المرطبان (يتطلب حساباً) والفائزون السابقون              |
| /admin/settings       | واتساب، الشحن والتوصيل المجاني، نصوص الهيرو، شريط الإعلان، وسلوكيات المتجر           |
| /admin/reviews        | اعتماد أو رفض التقييمات                                                              |
| /admin/studio         | رفع الصور والفيديو ونسخ روابطها                                                      |
| /q/haytham            | بطاقة التواصل القديمة دون تغيير الرابط المطبوع، مع QR وvCard                         |
| /cart                 | سلة محفوظة على الجهاز وإرسال الطلب إلى واتساب                                        |
| /manifest.webmanifest | تثبيت PWA مع أيقونات وصفحة عدم الاتصال                                               |
| /sitemap.xml          | روابط الصفحات والمنتجات والخلطات المنشورة والمقالات                                  |
| /api/health           | صحة الاتصال بقاعدة البيانات دون عرض أسرار                                            |

تُحفظ السلة كطلب `PENDING` بأسعار الخادم **قبل** فتح رسالة واتساب. عند فشل الحفظ يظهر خطأ وتبقى السلة، وإعادة المحاولة لا تكرر الطلب. تغيير السعر يتطلب مراجعة العميل. نقرة واتساب أو الطلب الجديد لا تعني دفعاً أو بيعاً مؤكداً. يؤكد الفريق الاتفاق، ويتابع التجهيز والتوصيل والتسليم من الإدارة.

`/admin/orders` يعرض مراحل الطلب وموعد المتابعة وسبب الإلغاء. الإلغاء يسوّي النقاط ويحفظ السجل، ولا تُحذف الطلبات نهائياً من الواجهة. `/admin` يفرق بين نشاط الزوار ونتائج الطلبات وقيمتها التقديرية. المخزون العددي وتنبيهات الندرة غير مستخدمة، و`/api/stock-alerts` و`/feeds/products.xml` يعيدان 410؛ SEO لصفحات المنتجات وخريطة الموقع مستمران دون ادعاء توفر مخزون.

الحملات تبدأ بقرار المسؤول من `/admin/campaigns`، وتعالجها المهمة المجدولة الموثقة في [دليل VPS](deploy/VPS.md). صفحة الإدارة لا تحتاج البقاء مفتوحة. الإرسال التجريبي لا يتم إلا إلى بريد يحدده المسؤول. لا تُفعّل أي حملة أو خصم بتثبيت هذا الإصدار.

## VPS

التعليمات الكاملة: [deploy/VPS.md](deploy/VPS.md).

- Docker Compose: PostgreSQL مستقل، migrations قبل بدء التطبيق، والتطبيق بمستخدم غير root.
- الاستديو في volume دائم، وليس داخل public أو صورة Docker. يظل رابط /uploads/studio/... صالحاً بعد إعادة النشر.
- Nginx على الخادم ينهي HTTPS ويحدّ من حجم الطلبات والمحاولات. منفذ التطبيق مربوط بـ127.0.0.1 فقط.
- واجهات الكتابة تتحقق من Origin، وجلسات الأدمن HttpOnly وموقّعة بسر إلزامي. حدود المحاولات مشتركة في PostgreSQL.
- رفع الملفات يفحص النوع الفعلي والحجم، ويرفض SVG/HTML. تنزيل الفيديو يدعم Range.
- تغيير صورة منتج يتم برفعها من الاستديو ثم نسخ رابطها إلى محرر المنتج؛ لا يمكن حذف صورة مستخدمة في منتج أو خلطة.
- الصفحات المعتمدة على البيانات تُنشأ على الخادم وقت الطلب؛ **البناء لا يحتاج اتصالاً بقاعدة البيانات ولا أسرار الإنتاج**. هذا يختار حداثة الأسعار وسهولة النشر مقابل استعلامات أكثر، وهو مناسب لكتالوج صغير. راقب الحمل قبل إضافة cache.
- ملفات الاستديو ليست جزءاً من Git ولا نسخ التطبيق؛ انسخها احتياطياً مع القاعدة.
- روابط المنتجات الحالية ثابتة لحماية SEO. إخفاء منتج يجعله غير متاح مباشرة ويزيله من Sitemap.

## الاختبارات

```bash
npm run lint
npm run typecheck
npm run test:run
npm run format:check
NEXT_PUBLIC_SITE_URL=https://alhaythamhoney.sy npm run build
npm start
```

لتشغيل اختبارات التكامل أيضاً، اضبط `TEST_DATABASE_URL` على قاعدة محلية مخصصة للاختبار ينتهي اسمها بـ`_test` ثم طبّق الترحيلات عليها. **اختبارات التكامل تنظف بيانات قاعدة الاختبار**؛ لا تستخدم بيانات تريد الاحتفاظ بها. دون هذا المتغير تُتخطى اختبارات التكامل العشرة.

الاختبارات الوحدوية تختبر الجلسات والحدود والـAPI وحساب الخلطات والسلة وvCard والملفات. اختبارات SQL تعمل داخل PGlite (PostgreSQL/WASM)، ولا تستبدل اختبار PostgreSQL 16 الفعلي.

CI في .github/workflows/ci.yml يستخدم PostgreSQL 16: يطبق migrations مرتين، يفحص عدم وجود اختلاف بين القاعدة والمخطط، ويبني ثم يجري اختبارات Playwright على الموبايل. لا ينشر الموقع تلقائياً.

Next.js مثبّت على 16.3.5. يوجد override محدد لـdeepmerge-ts 8 داخل أدوات Prisma لمعالجة التنبيه الأمني دون تغيير الإصدار الرئيسي لـPrisma؛ راجعه عند ترقية Prisma. افحص اعتماديات الإنتاج بـ`npm audit --omit=dev` دورياً.

لتشغيل اختبارات المتصفح محلياً، استخدم **قاعدة اختبار فارغة فقط** اسمها ينتهي بـ_test، وNEXT_PUBLIC_SITE_URL=http://127.0.0.1:3005 عند البناء والاختبار معاً:

```bash
npx playwright install chromium
npm run db:deploy
npm run build
npm run test:e2e
```

اختبارات E2E تضيف حساب e2e-admin ومنتج e2e-honey داخل قاعدة الاختبار فقط، وترفض عنوان موقع خارجي. لا تستخدم إعدادات الإنتاج معها.

## قيود يجب مراجعتها قبل الإطلاق

- مراجعة الأسعار والأوزان من إدارة المنتجات، وأجرة الشحن وحد الشحن المجاني من إدارة الإعدادات.
- مراجعة النصوص والادعاءات الصحية، البيانات التجارية والبريد والعنوان وساعات العمل؛ هذه التعديلات البرمجية ليست تدقيقاً طبياً أو قانونياً للمحتوى.
- متابعة موافقة HTTPS وGoogle Search Console، وتجربة QR مطبوع، وطلب واتساب فعلي، ورفع فيديو ثم إعادة النشر والتأكد من بقائه.
- أحداث الموقع مجهولة الهوية محفوظة محلياً لمدة 90 يوماً. نسبة تأكيد الطلبات تستخدم نفس مجموعة الطلبات المسجلة؛ ليست نسبة تحويل زوار فريدين، ولا تحسب الأرباح أو التحصيل.
- PWA تحفظ السلة محلياً وتعرض صفحة اتصال بديلة، ولا تخزّن صفحات الأسعار أو الإدارة دون اتصال.
- تدوير ADMIN_SESSION_SECRET يبطل جميع جلسات الأدمن. Seed لا يغيّر كلمة مرور حساب موجود.

مراجع التنفيذ: [استضافة Next.js ذاتياً](https://nextjs.org/docs/app/guides/self-hosting)، [Web App Manifest](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/manifest).
